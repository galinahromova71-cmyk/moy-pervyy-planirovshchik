# Концепция проекта: личный планировщик контента

## 1. Идея

Личный веб-планировщик для подготовки публикаций в Telegram-канал бухгалтерского агентства. Он помогает собирать идеи, планировать даты, сохранять заметки и черновики, а затем видеть, на каком этапе находится каждая публикация.

На первом этапе это учебный проект на HTML, CSS и JavaScript. Данные хранятся в браузере через `localStorage`: сервер и база данных не нужны. Интерфейс стоит проектировать так, чтобы позже его можно было постепенно развивать для реального использования.

## 2. Для кого и о чём канал

Канал рассказывает о работе бухгалтерского агентства и постепенно знакомит аудиторию с расширением услуг до консалтинга и функций финансового директора (CFO):

- бухгалтерское сопровождение;
- управленческий учёт и управленческая отчётность;
- бюджетирование и финансовое планирование;
- финансовый директор для бизнеса и комплексное сопровождение.

В начале планировщик рассчитан на одну площадку — Telegram. Поле площадки можно предусмотреть в структуре публикации, чтобы позже добавить MAX, но интеграции и автоматическую публикацию в первой версии не делать.

## 3. Основной сценарий

1. Пользователь добавляет идею — из календаря или кнопкой «Новая публикация».
2. Заполняет тему, предполагаемую дату и, при желании, заметки или черновик.
3. Меняет статус по мере подготовки: «Идея», «В работе», «Готово», «Опубликовано».
4. Переносит дату, если планы изменились.
5. Просматривает записи в календаре, списке или по статусам.
6. При необходимости сохраняет резервную копию данных.

## 4. Что хранить в публикации

Минимальные поля для первой версии:

- тема или рабочий заголовок;
- планируемая дата;
- статус;
- заметки и идеи;
- черновик текста (необязательное поле);
- дата создания и дата последнего изменения.

Полезные, но необязательные поля, которые можно добавить после первого прототипа:

- рубрика, например «Бухгалтерия», «Управленческий учёт», «Бюджетирование», «CFO»;
- формат: текст, подборка, инструкция, кейс, мнение;
- фактическая дата публикации.

На старте лучше не делать обязательными много полей: запись должна быстро создаваться даже тогда, когда пока есть только тема и идея.

## 5. Статусы

Использовать четыре понятных статуса:

- **Идея** — тема записана, разработка ещё не началась;
- **В работе** — готовится материал;
- **Готово** — публикация подготовлена;
- **Опубликовано** — материал уже вышел.

Статус должен быть заметен в календаре и списке, например через подпись и мягкий цветовой маркер. Цвет не должен быть единственным способом различать этапы.

## 6. Экраны и способы просмотра

Предлагается сделать три представления с общими данными:

1. **Календарь** — основной обзор планируемых дат. Месяц удобен как исходный режим, потому что он даёт общий план без необходимости заранее определять частоту публикаций.
2. **Список** — записи по датам с удобным поиском и фильтрами; на телефоне это может быть самым компактным способом просмотра.
3. **По статусам** — доска с колонками «Идея», «В работе», «Готово», «Опубликовано», чтобы видеть ход подготовки.

Диапазон просмотра не нужно жёстко ограничивать календарным месяцем: нужны переходы между месяцами и режим списка с произвольным периодом. Позже можно добавить недельный обзор, если он окажется полезным.

### Создание и перенос

- Нажатие на день календаря открывает форму новой публикации с уже выбранной датой.
- На компьютере публикацию можно перетаскивать на другой день или в другую колонку статуса.
- На телефоне перенос должен быть доступен и без перетаскивания: через редактирование даты и статуса. Это важно, потому что перетаскивание пальцем может быть неудобным.

## 7. Поиск и фильтры

Для начала достаточно:

- поиска по теме, заметкам и черновику;
- фильтра по статусу;
- фильтра по дате или диапазону дат;
- сброса фильтров одной кнопкой.

Фильтр по рубрике можно добавить вместе с полем «Рубрика».

## 8. Визуальное направление

Рекомендованный вариант — **спокойный деловой интерфейс с зелёной палитрой**:

- тёплый светлый фон, чтобы экран не выглядел холодным;
- тёмно-зелёный для заголовков и основных действий;
- шалфейный или мягкий оливковый для вторичных элементов;
- один неброский тёплый акцент, например терракотовый, для выделений;
- простой читаемый шрифт и достаточно свободного пространства.

Такой стиль поддерживает деловую тематику и остаётся дружелюбным для личного творческого планирования.

Возможные направления для дальнейшего выбора:

- **Строгий рабочий:** белый и светло-серый фон, графитовый текст, зелёные акценты, компактные таблицы.
- **Мягкий природный (рекомендован):** молочный фон, зелёные оттенки, мягкие карточки и небольшие цветовые метки.
- **Деловой с творческими акцентами:** нейтральная основа, зелёный интерфейс и разные спокойные оттенки для рубрик, плюс выразительные карточки идей.

Сначала разумно реализовать второй вариант, сохранив структуру достаточно простой, чтобы позже поменять цвета и плотность интерфейса. Интерфейс проектируется в первую очередь для телефона, но должен хорошо перестраиваться для ноутбука: календарь адаптируется по ширине, а формы и карточки остаются удобными для нажатия пальцем.

## 9. Хранение и резервная копия

Данные сохраняются в `localStorage` текущего браузера. Это просто для учебного проекта и работает без сервера, но данные не синхронизируются автоматически между телефоном и ноутбуком и могут потеряться при очистке данных браузера.

Поэтому экспорт и импорт стоит включить в раннюю версию:

- **экспорт в JSON** — полная резервная копия, которую можно затем импортировать обратно;
- **импорт из JSON** — восстановление записей с проверкой формата и понятным сообщением об ошибке;
- перед импортом показывать предупреждение, если он заменит текущие записи, и предложить сначала скачать резервную копию;
- дополнительно можно сделать экспорт в CSV для просмотра таблицы в электронных таблицах, но это не заменяет JSON-копию.

Для учебного MVP достаточно JSON-экспорта и JSON-импорта. Никакие данные не отправляются на сервер.

## 10. Состав первой версии (MVP)

1. Адаптивная страница для телефона и ноутбука.
2. Создание, просмотр, редактирование и удаление публикаций.
3. Тема, дата, статус, заметки и необязательный черновик.
4. Календарь, список и доска по статусам.
5. Перенос даты: перетаскиванием на компьютере и через форму на телефоне.
6. Поиск, фильтр по статусу и выбор периода.
7. Автосохранение в `localStorage`.
8. Резервный экспорт и восстановление из JSON.

## 11. Что оставить на следующий этап

Чтобы первая версия оставалась посильной для обучения, отложить:

- автоматическую публикацию и интеграцию с Telegram или MAX;
- синхронизацию между устройствами;
- напоминания и уведомления;
- совместную работу нескольких пользователей;
- аналитику просмотров и эффективности публикаций;
- сложные повторяющиеся расписания.

Эти функции потребуют дополнительных решений и, вероятно, сервера или интеграций. Их можно пересмотреть после того, как станет понятно, как планировщик используется на практике.

## 12. Предлагаемый путь разработки

1. Сначала определить поля публикации и сделать простую форму с сохранением в браузере.
2. Добавить список записей и статусы.
3. Сделать календарь и создание публикации нажатием на дату.
4. Добавить поиск, фильтры и доску по статусам.
5. Улучшить мобильное отображение и добавить перенос записей.
6. Добавить импорт и экспорт JSON.

Так каждый шаг даёт видимый результат и помогает постепенно понять HTML, стили, обработку действий пользователя и хранение данных в браузере.
